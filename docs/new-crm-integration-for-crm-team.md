# FortressFX New CRM Payment Integration

This document is for the new CRM team.

## Overview

The CRM creates an INR deposit payment by calling Fortress Pay. Fortress Pay creates the PSP payment and returns only the PSP-hosted payment URL. The CRM should redirect the customer directly to that URL.

## Create Payment

```http
POST https://pay.fortressfx.com/api/new-crm/payment
```

Headers:

```http
Content-Type: application/json
x-admin-key: SHARED_ADMIN_PANEL_KEY
```

Request body:

```json
{
  "transactionId": "CRM-TRANSACTION-ID",
  "username": "BANK-ACCOUNT-HOLDER-NAME",
  "email": "REGISTERED-EMAIL-ADDRESS",
  "mobile": "10-DIGIT-MOBILE-NUMBER",
  "amount": 10000
}
```

Field rules:

- `transactionId`: unique transaction ID generated by CRM.
- `username`: bank account holder name.
- `email`: registered customer email.
- `mobile`: 10 digit mobile number.
- `amount`: INR amount. Do not send USD. Do not convert to INR before calling unless the CRM amount is not already INR.

Do not send callback URL, webhook URL, return URL, internal transaction ID, or PSP transaction ID.

## Success Response

```json
{
  "paymentUrl": "https://lobby.dxbpay.me/?token=..."
}
```

The CRM must redirect the customer to `paymentUrl`.

No other fields are returned.

## Idempotency

The CRM must use the same `transactionId` for retrying the same payment request.

If the same `transactionId` is sent again with identical details, Fortress Pay returns the same PSP payment URL and does not create a second PSP payment.

If the same `transactionId` is reused with different details, Fortress Pay returns:

```http
409 Conflict
```

```json
{
  "error": "transactionId already exists with different payment details"
}
```

## Payment Status Callback

Fortress Pay sends payment confirmation to the configured CRM webhook URL.

Callback headers:

```http
Content-Type: application/json
privatekey: SHARED_NEW_CRM_WEBHOOK_PRIVATE_KEY
```

Callback payload:

```json
{
  "transactionId": "CRM-TRANSACTION-ID",
  "status": "completed",
  "utr": "BANK-REFERENCE"
}
```

`utr` can be `null`.

Supported status values:

- `pending`
- `completed`
- `failed`
- `cancelled`
- `expired`

## Postman Test

Set Postman variables:

```text
baseUrl=https://pay.fortressfx.com
adminKey=SHARED_ADMIN_PANEL_KEY
```

Create payment request:

```http
POST {{baseUrl}}/api/new-crm/payment
```

Headers:

```http
Content-Type: application/json
x-admin-key: {{adminKey}}
```

Body:

```json
{
  "transactionId": "CRM-TEST-001",
  "username": "Test User",
  "email": "test@example.com",
  "mobile": "9876543210",
  "amount": 10000
}
```

Expected success:

```json
{
  "paymentUrl": "https://lobby.dxbpay.me/?token=..."
}
```

Retry test:

- Send the exact same request again.
- Expected: same `paymentUrl`.

Conflict test:

- Send the same `transactionId` with a different `amount`, `email`, `mobile`, or `username`.
- Expected: `409 Conflict`.
