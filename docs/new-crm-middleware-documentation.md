# Payment API For New CRM

This document is for the New CRM integration team.

## Create Payment

Use this API to create an INR deposit payment.

Staging URL:

```http
POST https://fortress-pay-8pdyx.ondigitalocean.app/api/new-crm/payment
```

Production URL:

```http
POST https://pay.fortressfx.com/api/new-crm/payment
```

## Headers

```http
Content-Type: application/json
privatekey: SHARED_API_KEY
```

## Request Body

```json
{
  "transactionId": "CRM-TRANSACTION-ID",
  "username": "BANK-ACCOUNT-HOLDER-NAME",
  "email": "REGISTERED-EMAIL-ADDRESS",
  "mobile": "10-DIGIT-MOBILE-NUMBER",
  "amount": 10000
}
```

Field details:

- `transactionId`: unique payment ID generated by New CRM.
- `username`: customer bank account holder name.
- `email`: customer registered email address.
- `mobile`: customer 10 digit mobile number.
- `amount`: payment amount in INR.

Do not send amount in USD.

Exchange rate handling is owned by New CRM. If the customer balance or wallet is in USD, New CRM should calculate the final INR amount before calling this API.

Minimum and maximum deposit limits per transaction are also owned by New CRM. New CRM should validate those limits before calling this API.

## Success Response

```json
{
  "paymentUrl": "https://stagelobby.swrpay.com/dashboard?token=..."
}
```

Redirect the customer to `paymentUrl`.

## Return URL

After the customer completes the payment page flow, they will be returned to the configured return page.

Current return URL:

```text
https://my.fortressfx.com/en/funds/deposit?currencyId=68&transactionCurrencyAlpha=INR&methodId=16
```

New CRM does not need to send a return URL.

## Idempotency

Use the same `transactionId` when retrying the same payment request.

If the same `transactionId` is sent again with the same details, the same payment URL is returned.

If the same `transactionId` is sent again with different details, the API returns:

```http
409 Conflict
```

```json
{
  "error": "transactionId already exists with different payment details"
}
```

## Payment Status Callback

Payment result updates will be sent to the New CRM callback URL configured during onboarding.

Callback method:

```http
POST
```

Callback headers:

```http
Content-Type: application/json
privatekey: SHARED_CALLBACK_KEY
```

Callback body:

```json
{
  "transactionId": "CRM-TRANSACTION-ID",
  "status": "completed",
  "utr": "BANK-REFERENCE"
}
```

`utr` may be `null`.

Supported statuses:

- `pending`
- `completed`
- `failed`
- `cancelled`
- `expired`

Credit the customer only when:

```json
{
  "status": "completed"
}
```

```json
  "amount": 100

```

Expected response:

```json
{
  "paymentUrl": "https://stagelobby.swrpay.com/dashboard?token=..."
}
```

For every new test, use a new `transactionId`.

## Amount And Limit Handling

The API receives the final INR amount from New CRM.

New CRM is responsible for:

- INR to USD / USD to INR exchange-rate calculation.
- Minimum deposit amount validation.
- Maximum deposit amount validation.
- Showing any exchange-rate or limit information to the customer.

The API will process the INR `amount` received in the request.

## Error Responses

Invalid API key:

```http
401 Unauthorized
```

```json
{
  "error": "Invalid admin key"
}
```

Invalid request:

```http
400 Bad Request
```

```json
{
  "error": "Invalid payment request",
  "details": ["email must be a valid email address"]
}
```

Duplicate `transactionId` with changed details:

```http
409 Conflict
```

```json
{
  "error": "transactionId already exists with different payment details"
}
```
